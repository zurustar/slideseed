# SlideSeed

**Markdownから、プロフェッショナルなプレゼンテーションを。**

SlideSeedは、Markdown形式で記述したテキストを、コンサルティング資料のような洗練されたプレゼンテーションに変換する、ブラウザベースのツールです。

## コンセプト

**伝えたい内容と、スライドのデザインを分離する。**

ユーザーはスライドのメッセージと論理構造をMarkdownで記述します。SlideSeedは、その内容をあらかじめ定義されたスライドデザインパターンに当てはめ、視覚的に整理されたプレゼンテーションを生成します。

スライドのデザインを一から考える必要はありません。

## 主な特徴

- **Markdownベース**：シンプルなテキストでスライドを記述
- **プロフェッショナルなデザイン**：比較、プロセス、マトリクス、階層図などの標準パターンを提供
- **リアルタイムプレビュー**：Markdownの編集結果を即座に反映
- **単一HTMLファイル**：インストールやサーバーを必要とせず、ブラウザだけで動作
- **完全オフライン**：インターネット接続や外部サービスを必要としない
- **プレゼンテーション機能**：全画面表示、スライド切り替え、PDF出力
- **AIとの親和性**：生成AIによるMarkdownの生成・編集が容易

## 使用イメージ

以下のMarkdownから左右比較型のスライドを生成します。

```markdown
# AI駆動開発への転換
<!-- layout: compare -->

## 従来型
- 人がコードを書く
- AIはコード補完
- 既存プロセスを維持

## AI駆動型
- AIがコードを書く
- 人が仕様と品質を管理
- プロセス全体を再設計

> 実装主体の転換が本質
```

## 設計思想

1. **Content First** — 伝えたいメッセージと論理構造を優先する
2. **Design by Convention** — 厳選されたデザインパターンによって品質を担保する
3. **Zero Installation** — HTMLファイルを開くだけで使える
4. **Offline First** — 外部通信を必要としない
5. **AI Friendly** — 生成AIが容易に生成・理解できる記述形式を採用する
6. **Portable** — Markdownテキストだけでプレゼンテーションの内容を共有できる

## 現在の実装：基本エンジン + 12パターン

`index.html` をダウンロードしてChrome / Edgeで開いてください。単一ファイルで完全オフライン動作し、追加のインストールやビルドは不要です。

基本の6パターンは `message`（キーメッセージ）、`compare`（左右比較）、`pillars`（3本柱）、`process`（3〜5工程のプロセスフロー）、`matrix`（2×2マトリクス）、`problem-solution`（課題・原因仮説・対策の対応図）です。追加の第2群6種は下記の一覧を参照してください。左でMarkdownを編集し、右でスライドを選択・確認できます。Markdownの読込・保存、全画面発表、ブラウザ印刷によるPDF出力、構造・文字量・はみ出し警告を備えています。サンプルは初期表示され、[samples/demo.md](samples/demo.md) にも収録しています。

要件の6種類と第2群の6種類は実装済みですが、[要件定義](docs/requirements.md) の実表示・印刷品質などの完成条件には未確認項目があるため、MVP全体の完成宣言とは区別します。

記法の確定事項、実装済み・未実装の一覧、テスト手順と未確認事項は [実装記録](docs/implementation.md) を参照してください。開発用の解析テストは追加依存なしで `node tests/run.cjs`、ブラウザ検証ページの生成は `node tests/browser.test.cjs` で実行できます（Node.jsは開発テストのみで使用し、利用者には不要です）。現環境ではブラウザ実機検証を完了できていないため、配布前に実装記録の手動確認を行ってください。

プロセスフローは `<!-- layout: process -->` で指定します。各 `##` を工程、段落を説明、箇条書きを成果物として扱います。[入力例](samples/process.md)を参照してください。工程数が3〜5以外の場合は、誤った図解を避けるため入力確認表示に切り替えます。

マトリクスは `<!-- layout: matrix -->` と横・縦それぞれの軸指定を使います。象限の順序は左上・右上・左下・右下です。[入力例](samples/matrix.md)を参照してください。軸の欠落・重複・不正、象限数の過不足がある場合は、内容を保持した入力確認表示に切り替えます。

課題・対策の対応図は `<!-- layout: problem-solution -->` を指定します。各 `##` を論点の行にし、その下に `- 課題:`、`- 原因:`、`- 対策:` を1件ずつ記述します。[入力例](samples/problem-solution.md)を参照してください。原因は仮説として表示し、未知・不足・重複フィールドを警告します。


## 第2群：説明と意思決定

次の6パターンを追加しました。各IDを `<!-- layout: ID -->` で明示指定します。追加構文の完全な仕様・上限・未確認事項は [第2群の実装記録](docs/group2.md)、6種まとめた入力例は [samples/group2.md](samples/group2.md) を参照してください。初期サンプルには全12種を収録しています。

| ID | 用途 | サンプル |
| --- | --- | --- |
| logic-tree | 親子関係で論点を分解 | [入力例](samples/logic-tree.md) |
| pyramid | 結論を支持理由で支える | [入力例](samples/pyramid.md) |
| roadmap | 施策の時期・並行関係 | [入力例](samples/roadmap.md) |
| evaluation | 同じ基準で複数案を比較 | [入力例](samples/evaluation.md) |
| kpi | 実績・目標・単位・期間を表示 | [入力例](samples/kpi.md) |
| recommendation | 提言と担当・期限付きアクション | [入力例](samples/recommendation.md) |

追加依存なしの開発テストは `node tests/run.cjs` で実行できます。ブラウザ検証ページは `node tests/browser.test.cjs` で生成します。実ブラウザでの日本語表示・全画面・PDF品質は今回も未確認であり、ユーザーによる表示確認後にマージする運用です。第3群は未実装です。
