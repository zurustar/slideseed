# 第2群：説明と意思決定の6パターン

Issue #6〜#11の実装。要件の正本 `requirements.md` は変更しない。配布物は従来どおり単一の `index.html`。実行時の外部通信・ライブラリ・フォント取得・永続保存を追加しない。

## 共通ルール

新規パターンは `<!-- layout: ID -->` で明示指定する。レイアウト未指定時の見出し2個→compare、3個→pillars、それ以外→messageは変えない。独立したコメント行で追加ディレクティブを指定し、指定位置は見出しの前後どちらでもよい。各ディレクティブは所有するlayout内でのみ解釈し、他layoutでは文字として表示する。

必須項目・構造・数値が成立しない場合は、図解を確定せず、警告とスクロールできる原文表示に切り替える。エディタと保存内容は自動修正しない。推奨文字量を超えても削除・要約・文字サイズの自動縮小は行わない。各部品の実寸測定と文字量警告を併用する。個別の文字数目安をすべて同時に上限まで使えるという保証ではない。長いタイトル、補足、結論が同居する場合はスライド分割が必要になる。

## パターン仕様

| ID / Issue | 入力・制約 | 表現 |
| --- | --- | --- |
| `logic-tree` / #6 | `<!-- root: ... -->` 必須。見出し2〜3個を親、各箇条書き1〜2件を子。全体10ノード以内。root・親・子は18字、各親の補足段落は合計24字を推奨。箇条書きのインデントは禁止。 | 左からルート・親・子。固定階層の直交接続線で関係を示し、任意の再分類・MECE判定・数式計算はしない。 |
| `pyramid` / #7 | `>` が結論、見出し2〜3個が支持理由。複数の引用行は空白で連結。結論50字、見出し16字、各補足1件40字を推奨。余分な補足は保持して警告。 | 上段の横長の結論と、下段の根拠を線で接続。三角形に文字を押し込めない。 |
| `roadmap` / #8 | 表の先頭列「施策」、期間3〜6列、施策3〜5行。期間名8字・施策名16字を推奨。「実施」は各行で連続させ、「-」は非実施。全期間「-」の行も明示的な非実施として許可。 | 等幅の期間列に対し、連続セルをまとめたバーを表示。実日数比例・日付推測・依存線は扱わず、その旨を注記する。 |
| `evaluation` / #9 | 表の先頭列「判断基準」、案2〜4列、基準3〜5行。案名・基準名・セル根拠は各12字を推奨。セルは `◎ 根拠` / `○ 根拠` / `△ 根拠` / `× 根拠` / `未評価`。任意の `<!-- recommend: 案名 -->` は表の案名と完全一致させる。 | 記号と固定凡例、根拠、明示指定された推奨列の枠を表示。推奨案名も文字で示す。未評価は「— 未評価」で、×不適合と区別。自動の順位・加重スコア・勝者判定はない。 |
| `kpi` / #10 | `<!-- period: ... -->` 必須。指標3〜4個。各見出し内に `- actual:` / `- target:` / `- unit:` 各1つ。通常段落は補足。指標名12字・数値8桁（符号と小数点を除く）・単位8字・補足合計30字・測定期間30字を推奨。 | 大きな実績数値、単位、目標、期間を表示するカード。値は入力した文字列を保持。達成率や指標の良否を推測しない。 |
| `recommendation` / #11 | `>` が提言。「判断理由」と「次のアクション」の見出しを各1つ。理由は箇条書き2〜3件、アクションは `- action:` / `- owner:` / `- due:` 各1件。見出しやフィールドの入力順は任意。提言50字・理由各30字・実行内容40字・担当と期限各20字を推奨。 | 提言の下で左に判断理由、右に実行内容・担当・期限を分離。実行欄の罫線で強調し、承認済みと判断したり担当を補完したりしない。 |

KPI数値は `+` / `-` の符号を許す十進整数または小数（例：`-0.25`、`0`、`123.00`）。小数点前後には数字が必要。指数・カンマ・単位付き数値・NaN・Infinity・16進数・欠測文字列はエラー。数値へ変換して有限性は検証するが、表示は元の値を保持し、丸め・千/万への変換はしない。

予約フィールドの区切りは半角 `:` または全角 `：`。最初の区切り以降は内容として保持する。フィールドの重複・空値・未知のキーはエラー。KPI以外で予約フィールドが必須の箇所に通常段落を置いた場合もエラーにし、原文を表示する。

## 共通テーブル記法

roadmap / evaluationでのみ解析する最小サブセット。ヘッダー、区切り行、データ行を1つの表として記述する。全行を外側の `|` で囲み、区切り行は各列 `---` とする（整列の `:` も受け付けるが配置は標準テーマに統一）。空行は通常Markdownと同様に無視する。表の途中に補足段落を挟んで再開した場合は複数ブロックとしてエラー。

セル内の文字 `|` は `\|`、バックスラッシュは `\\` で記述する。それ以外のエスケープを特別解釈しない。行・列名の空欄/重複、区切り不正、セル数不一致、空セル、複数ブロック、表用layout内の `##` はエラー。意味不明なセルを「非実施」や「低評価」に置き換えない。通常の段落・箇条書きは表の前後の補足として表示する。

```markdown
# 先行導入と標準化を段階的に進める
<!-- layout: roadmap -->
| 施策 | 第1期 | 第2期 | 第3期 |
| --- | --- | --- | --- |
| 先行導入 | 実施 | 実施 | - |
| 標準化 | - | 実施 | 実施 |
| 全社展開 | - | - | 実施 |
> 検証結果を標準化へ引き継ぐ
```

各パターンの完全な入力例は `samples/logic-tree.md`、`samples/pyramid.md`、`samples/roadmap.md`、`samples/evaluation.md`、`samples/kpi.md`、`samples/recommendation.md`。第2群をまとめた `samples/group2.md` と、全12種を含む初期サンプル `samples/demo.md` も収録する。

## 実装とテスト

入力解析と描画は分離。追加コメント、予約フィールド、表の字句解析・矩形検証を共通化した。HTML入力は任意の場所でもテキストノードとして描画する。CSSで固定トポロジーの線・表・カードを作り、入力由来のタグやスクリプトを生成しない。

開発用Node.jsだけで実行でき、追加パッケージは不要：

```
node tests/run.cjs
node tests/browser.test.cjs
```

2026-10-27：**Nodeテスト70件成功**（既存28件＋第2群42件）。6サンプルの解析・描画構造、各上限要素数、欠落/重複/未知フィールド、非連続期間、セル数不一致、評価記号、未評価、推奨案参照、有限十進数、原文保持、安全な文字描画、旧layoutと自動選択の互換性を検証した。アプリとブラウザ検証ページのJavaScript構文検査、差分チェックも成功。

`tests/browser.generated.html` は全12初期サンプル、各新規layoutの構造、上限要素数の実測はみ出しチェック、不正入力時の原文表示を確認する自己完結したブラウザ検証ページ。実行時はPASS/FAILを表示する。全画面API・ファイル保存ダイアログ・印刷ダイアログはテストではスタブとしており、実操作確認の代替にはしない。

**ブラウザ検証ページは生成のみで、今回も実行結果は未確認。** DOMフィクスチャの構造テストはCSSを解釈しないため、日本語の視覚品質・接続線の衝突・印刷結果を保証しない。ブラウザのfile: URL制限を迂回せず、前回合意した運用に合わせて、通常PRをユーザーが表示確認後にマージする。未確認項目を完了扱いにしたり、正本の完成条件を緩和したりしない。
