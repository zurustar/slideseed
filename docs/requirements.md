# SlideSeed 要件定義書

- バージョン：0.1（初期要件）
- ステータス：Draft
- 対象：MVPおよび将来構想

## 1. プロジェクト概要

### 1.1 目的

SlideSeedは、Markdownテキストから、論理的に構造化されたプロフェッショナルなプレゼンテーションを生成するツールである。

利用者がPowerPointなどでレイアウトや装飾を手作業で調整する負担を減らし、プレゼンテーションの内容と論理構造の作成に集中できる環境を提供する。

### 1.2 解決したい課題

- プレゼン資料のレイアウト・デザインに多くの時間がかかる
- 作成者によってスライドのデザイン品質がばらつく
- 生成AIで作成した文章をプレゼン資料にする際、再編集が必要になる
- 制限の厳しい業務環境では、任意のアプリケーションをインストールできない
- PowerPointなどのファイルを受け渡せない環境でも、プレゼンテーションの本質的な情報を共有したい

### 1.3 提供価値

**テキストを記述するだけで、洗練されたプレゼンテーションを作成できる。**

スライドの内容をテキストデータとして管理し、デザインはツールが提供する標準パターンによって統一する。

## 2. 基本設計思想

### 2.1 内容とデザインの分離

プレゼンテーションを以下の2つに分離する。

- Content：主張、根拠、数値、論理構造、スライドの順序
- Design：レイアウト、タイポグラフィ、余白、配色、図形

ContentはMarkdownとして記述し、DesignはSlideSeed側で管理する。

### 2.2 Design by Convention

自由な配置を許すのではなく、あらかじめ厳選されたスライドパターンを提供する。

これにより、デザインの自由度を適切に制限し、一定以上の視覚品質を実現する。

パターンは単なるレイアウトではなく、比較、分類、因果関係、時間的推移などの論理構造と対応付ける。

### 2.3 Zero Installation

最終的な配布物は原則として単一のHTMLファイルとする。

利用者はHTMLファイルをローカルのブラウザで開くだけで利用できる。

- ソフトウェアのインストール不要
- 管理者権限不要
- Webサーバー不要
- インターネット接続不要
- 外部API不要
- CDN不要

JavaScript、CSS、必要なリソースはHTML内に含める。

### 2.4 AI Friendly

Markdownの記法は、生成AIが容易に生成・編集できることを重視する。

Microsoft 365 Copilot、GitHub Copilot、ChatGPTなど、特定のAIサービスに依存しない。

AIそのものはSlideSeedの動作に必須としない。

### 2.5 シンプルさと拡張性

最初からあらゆる表現に対応することは目指さない。

代表的なビジネススライドを高品質に表現できる最小限の機能を優先する。

## 3. 想定ユーザー

- ビジネスプレゼンテーションを作成する一般社員
- コンサルティング型の論理的な資料を作成したい利用者
- 生成AIを利用してプレゼンテーションを作成する利用者
- ソフトウェアを自由にインストールできない組織の利用者
- Markdownを利用した資料作成を好む技術者

## 4. ユーザー体験

### 4.1 基本的な利用フロー

1. ユーザーがSlideSeedのHTMLファイルをブラウザで開く
2. Markdownエディタが表示される
3. ユーザーがMarkdownを入力する
4. 入力内容からプレゼンテーションが生成される
5. 編集内容がリアルタイムでプレビューに反映される
6. 必要に応じてスライドパターンを変更する
7. 完成したプレゼンテーションを全画面表示する
8. Markdownを保存、またはPDFとして出力する

### 4.2 画面構成

デスクトップ利用を基本とする。

- 左ペイン：Markdownエディタ
- 右ペイン：スライドプレビュー
- ツールバー：ファイル操作、プレゼン開始、印刷など
- パターン一覧：利用可能なスライドパターンとサンプル

エディタとプレビューの表示幅は調整可能とすることが望ましい。

## 5. Markdown記法

### 5.1 基本方針

標準Markdownを基本とし、必要最小限の独自ディレクティブを追加する。

原則として、Markdown単体でも人が内容を理解できること。

### 5.2 基本構文

- `#`：スライドタイトル
- `##`：セクション・構成要素
- `-`：箇条書き
- `**...**`：強調
- `>`：キーメッセージ・結論
- `---`：スライド区切り
- `<!-- layout: xxx -->`：スライドパターン指定

これらは初期構文案であり、実装時に仕様を確定する。

### 5.3 サンプル

```markdown
# AI駆動開発への転換
<!-- layout: compare -->

## 従来型
- 人がコードを書く
- AIはコード補完

## AI駆動型
- AIがコードを書く
- 人が品質を管理

> 実装主体を人からAIへ移す
```

### 5.4 レイアウトの選択

- ユーザーはディレクティブでパターンを明示指定できる
- 指定がない場合は、Markdownの構造に基づいて既定のパターンを選ぶ
- 自動選択は決定的なルールに基づき、再現性を確保する
- MVPではAIによる自動判定は必須としない

### 5.5 記法の設計原則

- 人が手書きしやすい
- 生成AIが生成しやすい
- 構文が少ない
- 文章の可読性が高い
- 将来の拡張で既存のMarkdownを壊さない

## 6. スライドパターン

### 6.1 基本方針

コンサルティング資料で一般的な論理表現を参考に、標準的なスライドパターンを整備する。

パターンごとに、以下を定義する。

- パターンID
- 用途
- Markdown入力仕様
- レイアウト構造
- 構成要素の数と上限
- 推奨文字量
- スタイルと強調ルール
- 入力不備時の挙動

### 6.2 MVP対応パターン

最初のバージョンでは次の6種類を実装する。

1. `message`：タイトル・キーメッセージ
2. `compare`：左右比較 / Before-After
3. `pillars`：3本柱 / 主要要素の並列整理
4. `process`：プロセスフロー
5. `matrix`：2×2マトリクス
6. `problem-solution`：課題・原因・対策

### 6.3 将来拡張候補

- ロジックツリー
- ピラミッド構造
- ロードマップ / タイムライン
- 循環プロセス
- KPIダッシュボード
- 棒グラフ / 折れ線グラフ
- 構成比 / 割合
- 選択肢評価
- リスクマトリクス
- 意思決定ツリー
- 組織構造
- 結論・提言
- ファネル
- バリューチェーン
- システム構成図

将来的には20〜30種類以上の表現パターンを提供することを想定する。

ただし、すべてを独立実装するのではなく、共通のレイアウトエンジンから派生させることを優先する。

## 7. デザイン要件

### 7.1 基本テーマ

初期のデフォルトテーマは以下とする。

- スライド比率：16:9
- 背景：白（#FFFFFF）
- アクセントカラー：#CC0033
- フォント：Meiryo UI（使用できない環境では適切な日本語フォントにフォールバック）
- 基本文字色：視認性の高いダークグレー
- デザイン：シンプル、端正、ビジネス向け

### 7.2 デザイン原則

- スライドは原則として1枚1メッセージ
- タイトルは単なるテーマ名よりも、主張を表現することを推奨する
- 視覚的な階層を明確にする
- 余白を十分に確保する
- 色は意味のある強調に使う
- 不必要な装飾を避ける
- 箇条書きだけに頼らず、内容に適した図解を使用する
- スライド間でデザインの一貫性を保つ

### 7.3 文字量への対応

文字数が多い場合に、文字サイズを無制限に縮小してはならない。

想定以上の文字量に対しては、次のような対応を行う。

- 内容があふれる可能性を警告する
- 推奨文字数・項目数を提示する
- 必要に応じてスライド分割を促す
- 情報を勝手に削除・要約しない

MVPでは、警告表示を優先する。

### 7.4 画像

初期バージョンでは画像の埋め込みを対象外とする。

CSS、HTML、SVGなどで生成できる図形や簡単なチャートは利用可能とする。

## 8. 機能要件

### 8.1 Markdownエディタ

- テキストの入力・編集
- リアルタイムプレビュー
- サンプルMarkdownの挿入
- Markdownファイルの読み込み
- Markdownファイルの保存
- 複数スライドの記述

### 8.2 スライドレンダリング

- Markdown解析
- スライド単位への分割
- パターン選択
- レイアウト生成
- 共通テーマの適用
- 日本語テキストの適切な折り返し
- 入力エラーの検出と表示

### 8.3 プレゼンテーション

- 全画面表示
- 前後のスライドへの移動
- キーボードによる操作
- スライド番号の表示
- 全画面表示の終了

### 8.4 出力

MVPでは次に対応する。

- Markdownファイルの保存
- ブラウザ印刷によるPDF出力

将来的には次を検討する。

- PPTX出力
- SVG出力
- PNG出力
- QRコードによるMarkdownデータの受け渡し

### 8.5 サンプル・ヘルプ

- 各パターンのサンプル
- Markdown記法の説明
- パターンの選択ガイド
- 入力エラーの修正方法

## 9. 非機能要件

### 9.1 動作環境

- Windows / macOS の主要なデスクトップブラウザ
- Microsoft Edge
- Google Chrome

ブラウザの通常のセキュリティ制約内で動作すること。

### 9.2 オフライン動作

- HTMLをローカルファイルとして直接開ける
- インターネット接続不要
- 外部APIへの通信なし
- CDNへの依存なし
- サーバーへのデータ送信なし

### 9.3 配布形式

完成品は単一の `SlideSeed.html` とする。開発用エントリは `index.html` を維持し、配布時に同じ内容を `SlideSeed.html` として出力する。

このファイル名変更はIssue #26のユーザー要望に基づく。ヘルプ・サンプル・必要なライセンス通知もHTML内に保持し、利用時の追加ファイル依存は導入しない。

開発時はソースファイルを分割して管理してもよいが、配布時には単一ファイルへ統合する。

可能な限りビルドツールへの依存を減らす。

### 9.4 セキュリティ

- Markdownに含まれる任意のHTMLやJavaScriptを実行させない
- ユーザー入力を安全にエスケープする
- 外部通信を行わない
- 不必要に機密情報をブラウザへ永続保存しない
- ブラウザのセキュリティ制約を回避しない

### 9.5 性能

- 編集時のプレビューを快適に更新できる
- 複数スライドを含むプレゼンテーションを扱える
- スライド表示・切り替えを滑らかに行える

具体的な性能目標はMVPの実測後に設定する。

### 9.6 保守性

- Markdown解析とスライド描画を分離する
- 各パターンの描画処理を独立させる
- CSSの共通デザイントークンを使用する
- 構文仕様をドキュメント化する
- パターン追加時の既存機能への影響を抑える

## 10. 技術方針

### 10.1 基本技術

- HTML
- CSS
- JavaScript
- CSS Grid / Flexbox
- SVG

初期実装では、フレームワークを使用しないVanilla JavaScriptを基本とする。

### 10.2 Markdownパーサー

MVPで必要なMarkdown構文のみを解析する。

Markdownの完全実装を目指さず、SlideSeedが対応を宣言した構文を確実に処理する。

解析結果は、表示処理から独立したスライドデータ構造に変換することが望ましい。

### 10.3 レンダリングエンジン

Markdownから得られたスライドデータを、パターンIDに応じたHTML/CSS/SVGに変換する。

論理構造と描画処理を分離し、同じデータから再現性のあるスライドを生成する。

### 10.4 外部ライブラリ

外部ライブラリへの実行時依存を原則禁止する。

必要な場合は、ライセンスやセキュリティを確認したうえで、単一HTMLに同梱できる方式を検討する。

## 11. MVPの対象外

以下は初期実装では対応しない。

- AIモデルの組み込み
- PowerPointファイルの読み込み
- PowerPointファイルの直接出力
- 画像・動画・音声の埋め込み
- 高度なアニメーション
- 複数人による同時編集
- クラウドへの保存
- アカウント管理
- 外部API連携
- スライドの自由配置編集
- QRコード入出力

## 12. MVP完成条件

以下を満たしたとき、MVP完成と判断する。

1. 単一HTMLファイルをローカルで開いて動作する
2. Markdownを入力・編集できる
3. 複数スライドを生成できる
4. 6種類の標準パターンが利用できる
5. Markdownの修正がプレビューへ反映される
6. スライドショーを実行できる
7. Markdownを読み込み・保存できる
8. PDFへ印刷できる
9. 日本語表示で重大なレイアウト崩れが発生しない
10. 文字のはみ出しを検出・警告できる
11. 外部ネットワーク接続なしで利用できる
12. サンプルプレゼンテーションを用意する

## 15. プロジェクトの成功基準

SlideSeedの成功は、対応機能の多さではなく、次の観点で評価する。

**1. 簡単さ**

ユーザーがMarkdownを短時間で記述できる。

**2. デザイン品質**

ユーザーが細かくデザインを調整しなくても、洗練されたビジネススライドが生成される。

**3. 表現力**

標準的なビジネスプレゼンテーションの多くを、用意されたパターンで表現できる。

**4. 可搬性**

Markdownテキストを受け渡すだけで、プレゼンテーションを再現できる。

**5. 動作環境への依存の少なさ**

追加アプリケーションや外部サービスを必要とせず、一般的なブラウザだけで利用できる。

---

## 16. 最重要原則

**SlideSeedは、PowerPointの機能を再実装するツールではない。**

目的は、内容の記述を簡単にし、デザインの選択肢を意図的に制限することで、誰でも短時間で論理的かつ洗練されたプレゼンテーションを制作できるようにすることである。

機能の追加に際しては、常にこの原則を優先する。


## 17. MVP後の追加要件：MarkdownのQR表示

Issue #27のユーザー要望に基づき、編集欄の現在のMarkdown全文を単一QRコードとしてオフライン表示する。これは8.4・11・13で将来構想／MVP対象外としたQR機能のうち、出力表示のみの追加であり、元のMVP完成条件を変更しない。カメラ読込や複数QRの分割・復元は対象外とする。

UTF-8の原文を保持し、容量超過時は警告してMarkdown保存を案内する。無断の要約・省略・外部URL化・外部送信は行わない。表示・再生成はユーザーの明示操作で行う。詳細な符号化、容量、操作、制限と確認結果は [実装記録](distribution-qr.md) に記載する。
