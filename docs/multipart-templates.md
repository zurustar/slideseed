# 分割QRと選択テンプレート

Issue #29 / #30。単一HTML・オフライン動作と、既存21パターンを維持する。

## 空の原稿とテンプレート

初期の編集欄は空。プレビューには作成開始の案内を出し、空の間はプレゼン・印刷を無効にする。「テンプレートを挿入」から、用途の説明付き21種を選び、記入例のMarkdownを確認して挿入する。

空原稿には最初のスライドを追加。それ以外はプレビューで選択しているスライドの後へ挿入する。選択画面に挿入先を表示し、本文や表の途中には挿入しない。元の文字列を保持し、必要な区切り行と改行を追加する。CRLF等を含む原稿でも、パーサーと同じ区切りルールに対応する位置を元文字列上で求める。挿入後は追加したスライドをプレビューで選び、編集欄を該当位置へ移す。キャンセルで原稿は変わらない。

雛形は既存の検証済みサンプルを1枚ずつ利用し、必須の表・コメント・フィールドを保持する。全21種の原稿は内蔵ヘルプの「全21種のサンプルで置換」から明示的に呼び出せる。原稿がある場合には確認する。テンプレートの選択挿入とは別操作。

## QRの送り方

「QRコード」で、生成時点の編集欄全文を固定する。2,330 UTF-8バイト以内なら従来通りの生テキストQR。超える場合は自動で分割する。「前のQR」「次のQR」で移動し、番号／総数を確認する。自動送りはしない。原稿変更後は「現在の全文で再生成」または開き直す。生成中の再生成・閉じるは古い非同期結果を無効にする。

各QRは誤り訂正M、UTF-8 ECI、黒白、4モジュールの余白を維持する。長い原稿の上限は49,152 UTF-8バイト（1,536バイト×32個）。上限を超えたら切り捨てずMarkdown保存を案内する。メタデータとBase64の増加分を含む各QRのテキストは2,330バイト以内。

## 受け取り・復元

1. 送り手の全番号を一般的なQRリーダーで読み取る。
2. 受け手のSlideSeedで「分割QRを復元」を開く。
3. 読み取ったSSQR1テキストを1行ずつ貼り付け、「検証して復元」。順不同でもよい。同一番号・同一内容の重複はまとめる。
4. 不足番号があれば追記する。別原稿の混在、同じ番号の異なる内容、破損などはエラーになる。
5. 全体のSHA-256とUTF-8を検証後、復元原稿を確認欄に表示する。この時点では編集欄を変えない。
6. 「確認した原稿で編集欄を置き換える」を押す。原稿がある場合は確認を表示し、キャンセルで保持する。

単一QRはMarkdown原文なので、編集欄へ直接貼り付ける。分割QRの各文字列を単純に連結しても原文には戻らない。カメラの直接読込は未実装。復元ダイアログを閉じると貼り付けデータ・復元結果を消去する。復元中の入力変更も古い検証結果を無効にする。

## SSQR1プロトコル

各QRのペイロードは改行を含まないASCII文字列。

```
SSQR1:<digest>:<index>:<total>:<size>:<payload>
```

- `digest`：原文UTF-8バイト列のSHA-256、小文字16進64字。原稿組の識別と全体の破損確認に利用。暗号化や送り手の認証ではない。
- `index`：1始まりの番号。
- `total`：2〜32。ceil(size / 1536)と一致すること。
- `size`：原文UTF-8バイト数。2331〜49152。
- `payload`：番号に対応する最大1536バイトを、標準Base64（必要なパディング込み）にしたもの。最終部分以外は1536バイト固定。

UTF-8の途中でバイトを分割する場合もあるが、Base64は個別に復号し、全バイトを順に結合してからUTF-8を厳格に復号する。BOMも原文として保持する。メタデータ・長さ・正規Base64表現・重複の整合性・全体ハッシュを検証する。貼り付けの外側の空白と空行は無視。貼り付けは最大64行（重複込み）、149,120文字までとして入力処理の負荷も制限する。1行の上限は2330文字。未知バージョンは拒否。

SHA-256はブラウザ標準Web Cryptoを利用し、追加ライブラリや通信を使わない。crypto.subtleを提供しない環境では分割生成／復元に理由を表示する。推奨Chrome / EdgeのローカルHTMLでの動作確認は実機確認項目に含める。短い単一QRはWeb Cryptoを必要としない。

## 検証結果

`node tests/run.cjs`：163件成功。既存の単一QR・21パターンに加え、以下を検証。

- 独立デコーダーjsQRで各分割QRのピクセルを復号し、逆順・重複を含めて原稿を復元。日本語・絵文字・BOM・改行・空白・危険HTMLのUTF-8バイトが一致。
- 単一QRの2330バイト、分割2331バイト、チャンク境界、最大32個と49152バイト、超過。
- 欠落、混在、競合、破損、不正メタデータ、未知バージョン、不正UTF-8、SHA-256照合。
- UIモックで再生成／閉じる競合、復元前プレビューと確認、入力変更による無効化、選択挿入・キャンセル・連続挿入を確認。
- 全21種の雛形の構造・必須値に警告なし。先頭／中間／末尾、CRLF／CR／LF、BOM、空白、空スライド、表やコメントのある原稿で挿入を確認。

`node tests/browser.test.cjs`で空状態、選択挿入、QR送り、貼り付け復元などを含むブラウザ検証ページを生成。内蔵JSの構文チェックを実施。ブラウザ検証ページは未実行。

**未確認**：実ブラウザの操作・表示・ネイティブdialog、スマートフォンでの複数QR読取・ECI互換性、ローカルHTMLのWeb Crypto、編集位置へのスクロール、全画面・PDF・Windows日本語フォント。NodeのUIモックは実ブラウザ検証の代用ではない。表示をユーザーが確認してからマージする通常PRにする。公開済み0.0.1とリリース資産は変更しない。
