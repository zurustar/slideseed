# 単一HTML配布とMarkdownのQR表示

Issue #26 / #27 の初版実装記録。

以下のQR容量・対象範囲は0.0.1時点の記録。後続Issue #29 / #30で分割QRと選択テンプレートを追加したため、現在の操作・制限は [分割QRと選択テンプレート](multipart-templates.md) を参照。

## 配布

開発用ファイルは `index.html`。利用者向けには同一内容を `SlideSeed.html` として出力する。

```
python3 scripts/package.py 0.0.1
```

番号は出力物のラベルであり、このコマンドはタグやリリースを作成しない。`0.0.1`は次回用の例で、公開済み0.0.0の差し替えは行っていない。Pythonは開発・配布作業だけに必要で、利用者には不要。

`dist/` に以下を生成する。

- `SlideSeed.html`：これだけをChrome / Edgeで開く。
- `slideseed-0.0.1.zip`：ルート直下のSlideSeed.htmlだけを収録。
- `slideseed-0.0.1.sha256`：HTMLとZIPのSHA-256。

ZIPは固定タイムスタンプ・属性・順序で生成し、同じ環境と同じHTMLから同じバイト列になる。実装テストで内容・整合性・再現性・チェックサムを検証する。README・docs・samples・開発テスト・third_partyはリポジトリに残す。Releaseでは単体HTMLとZIP、チェックサムを添付し、GitHub自動生成のソースアーカイブと利用者向けZIPを区別する。ビルドを伴わないためActionsの新設は不要。

GPLv3全文とQRエンコーダーのMIT通知はHTMLに内蔵。「記法とレイアウトのガイド」内の「このアプリについて／ライセンス」でオフライン表示できる。ライセンスを省略して単一化する方式ではない。アプリの編集対象は配布HTML内の非圧縮コードであり、配布HTML自体に対応するソースを含む。リポジトリでも開発ソースと第三者コードを公開する。

## QRの操作と対象

1. Markdownを編集、またはファイルから読み込む。
2. 「QRコード」を押す。開いた時点のエディタ全文を使用する。未保存の変更も含む。
3. 一般的なQRリーダーでテキストを読み取り、コピーする。
4. 「閉じる」またはEscapeで閉じる。QRボタンにフォーカスを戻す。

モーダル表示中のコードは生成時点のスナップショット。「現在の全文で再生成」または開き直しで更新する。閉じるとキャンバスを消去する。QRは暗号化ではなく、表示を見た人が内容を取得できる。

UTF-8の原文をbyte modeとECI 26で符号化し、誤り訂正レベルM・バージョン1〜40とする。容量に合わせた訂正レベルの低下も、短文に対する自動上昇も行わない。上限はECI分込み **2,330 UTF-8バイト**。文字数ではない。短い入力は必要な最小バージョンを選ぶ。日本語は多くが1文字3バイト、絵文字は通常4バイト以上になる。

エディタの現在値から直接符号化するため、パーサーによる正規化・再構成・要約をしない。ただしtextareaへの読み込み時の改行正規化はブラウザの既存挙動であり、元ファイルのCRLFバイト列の保存を約束するものではない。不正な単独サロゲートは置換せずエラー表示。

空入力・容量超過・生成失敗時にはQRを残さず、理由とMarkdown保存の案内を表示。初期サンプルのような長い全文は1個に収まらない。自動分割・圧縮・一部だけの生成・URL化・外部送信はしない。

QRは黒白のCanvasで、4モジュールの余白と整数ピクセルのモジュールを持つ。表示が画面に収まらない場合はスクロール可能。読み取る際はウィンドウを広げるなどして、余白を含むコード全体を表示する。ブラウザの拡大率や端末によって読取品質が変わるため、実機の検証が必要。

QR画像保存、カメラ読込、複数QRの分割・復元、クラウド共有は未実装。

## 第三者コード

- Project Nayuki QR Code generator（MIT）：公式配布JSをHTMLへ同梱し、チェックインした `third_party/qrcodegen.js` との一致をテスト。出典とハッシュはthird_party/README.md参照。実行時の取得なし。
- jsQR（Apache-2.0）：独立した復号検証専用。tests/vendor内に配置し、利用者向けHTMLとZIPには含めない。

## 検証

`node tests/run.cjs`：147件成功（既存139＋配布1＋QR7）。QRは生成時と別のjsQRデコーダーにより、Canvasに描かれるピクセルを復号して照合する。日本語・絵文字・空白・改行・コメント・危険HTML・容量境界・バージョン・ECI・訂正M・余白・不正文字を検証。UIの状態遷移は小さいモックで確認。モックはブラウザの描画やネイティブdialogを検証しない。

`node tests/browser.test.cjs`：全21パターンの既存チェックに加え、QRモーダル・容量超過・再生成・閉じる・フォーカス復帰・ライセンス表示の検証ページを生成。

**未確認**：ブラウザ検証ページの実行、日本語の視覚品質、実際のCanvasの見え方、スマートフォンのQRリーダーでの読取とECI互換性、EscapeやTab操作を含むネイティブdialog、全画面、PDF、Windows日本語フォント。この環境ではこれらを実機確認できていない。ユーザーの表示確認後にマージする通常PRとする。
